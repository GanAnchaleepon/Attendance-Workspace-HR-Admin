# ระบบตรวจสอบข้อมูลเวลาการทำงานเบื้องต้น (TTV FTM-SE)

ระบบเว็บสำหรับ:
1. อัปเดตรายชื่อพนักงาน (Manpower / Manpower QA) จากไฟล์ HR
2. อัปโหลดไฟล์สแกนลายนิ้วมือ แยกตามโปรเจค (FTM-SE / AAT-SE)
3. คำนวณเวลาเข้า-ออกงานต่อกะ (กะเช้า 08:00-17:30 / กะดึก 22:30-08:00) และติดธง "อาจเป็น OT"
   ให้หัวหน้างานตรวจสอบ พร้อมพิมพ์ใบแจ้งการทำงานล่วงเวลา

สร้างด้วย PHP ล้วน (ไม่ใช้ framework/Composer) + MySQL เพื่อให้ใช้งานบน Hostinger shared hosting ได้ทันที

## โครงสร้างโปรเจค

```
attendance-system/
  index.php, login.php, dashboard.php, ...  -> หน้าเว็บ (เข้าถึงได้ผ่านเบราว์เซอร์)
  partials/, assets/                         -> ส่วนประกอบหน้าเว็บ (header/footer, css)
  src/                                       -> โค้ด PHP หลัก (ถูกกันไม่ให้เข้าถึงผ่านเว็บด้วย src/.htaccess)
  sql/schema.sql                             -> รันครั้งแรกใน phpMyAdmin เพื่อสร้างตาราง
  config.example.php                         -> คัดลอกเป็น config.php แล้วกรอกค่าฐานข้อมูลจริง
  .htaccess                                  -> กันการเข้าถึง config.php และไฟล์ระบบอื่น ๆ โดยตรง
```

ทุกไฟล์อยู่ระดับเดียวกัน (flat) เพื่อให้ **อัปโหลดทั้งโฟลเดอร์ทีเดียวลง `public_html` ได้เลย**
โดยไม่ต้องแยกไฟล์ไปไว้คนละตำแหน่ง — ความปลอดภัยของ `config.php`, `src/`, `sql/` ใช้วิธีกันด้วย `.htaccess`
(deny by filename/folder) แทนการซ่อนไว้นอก public_html

## วิธีติดตั้งบน Hostinger

1. **สร้างฐานข้อมูล MySQL** ใน hPanel > Databases > MySQL Databases
   จดชื่อฐานข้อมูล / username / password ที่ได้ไว้

2. **นำเข้าโครงสร้างตาราง**: เปิด phpMyAdmin ของฐานข้อมูลที่สร้าง แล้ว Import ไฟล์ `sql/schema.sql`
   (ถ้าเคย import ไปแล้วก่อนหน้า ให้ import ไฟล์ `sql/migration_2026_07_sort_order.sql` เพิ่มด้วยเพื่อเพิ่มคอลัมน์ที่ขาดไป)

3. **อัปโหลดไฟล์ผ่าน File Manager หรือ FTP**: อัปโหลด **เนื้อหาทั้งหมดในโฟลเดอร์ `attendance-system/`**
   (ไฟล์และโฟลเดอร์ข้างในทุกตัว รวมถึง `.htaccess`) ไปไว้ที่ `public_html/` โดยตรง (ไม่ต้องแยกเก็บนอก public_html)
   โครงสร้างบนโฮสต์ควรได้ประมาณนี้:
   ```
   public_html/
     index.php, login.php, dashboard.php, ...
     partials/
     assets/
     src/            <- มี .htaccess ของตัวเอง (deny all) ป้องกันการเข้าถึงผ่านเว็บ
     sql/            <- มี .htaccess ของตัวเอง (deny all) ป้องกันการเข้าถึงผ่านเว็บ
     config.php      <- ถูกกันด้วย .htaccess ที่ระดับ public_html (deny by filename)
     .htaccess
   ```
   ⚠️ ข้อควรระวัง: ห้ามมีโฟลเดอร์ `public/` ซ้อนอยู่ข้างในอีกชั้น — ไฟล์ `index.php`, `login.php` ฯลฯ
   ต้องอยู่ที่ระดับบนสุดของ `public_html` โดยตรง ไม่งั้นจะเข้าเว็บไม่ได้ (ขึ้น 403/404)

4. **สร้างไฟล์ config.php**: คัดลอกจาก `config.example.php` เปลี่ยนชื่อเป็น `config.php`
   แล้วกรอก host/ชื่อฐานข้อมูล/username/password ให้ตรงกับที่ได้จากข้อ 1
   วางไฟล์นี้ไว้ที่ระดับบนสุดของ `public_html` (เช่นเดียวกับ `index.php`) — ไฟล์นี้ถูกกันการเข้าถึงผ่านเว็บ
   ด้วย `.htaccess` อยู่แล้ว แต่ยังคงต้องเก็บรักษารหัสผ่านฐานข้อมูลไม่ให้รั่วไหลผ่านช่องทางอื่น

5. **เปิดเว็บไซต์ครั้งแรก** ระบบจะพาไปหน้า `setup.php` ให้ตั้งชื่อผู้ใช้/รหัสผ่านผู้ดูแลระบบ
   (ใช้ได้ครั้งเดียวตอนยังไม่มีผู้ใช้ในระบบ หลังจากนั้นหน้านี้จะใช้งานไม่ได้อีก)

6. เข้าสู่ระบบ แล้วเริ่มใช้งานตามลำดับ: อัปเดต Manpower -> อัปโหลดไฟล์สแกนนิ้ว -> ตรวจสอบ OT รายบุคคล

## หน้า "ตรวจสอบ OT" (ออกแบบใหม่)

- `attendance_review.php` แสดง**รายชื่อพนักงานทั้งหมดเรียงตามลำดับในไฟล์ Manpower** (Manpower หลักก่อน ตามด้วย Manpower QA)
  พร้อมสรุปจำนวนวันที่มีสแกนและวันที่ติดธง OT ของเดือนที่เลือก
- คลิก "ดูรายงาน" ของแต่ละคนเพื่อไปหน้า `print_ot_form.php` ซึ่งแสดง**ตารางเวลาทำงานรายวันทั้งเดือนของคนคนเดียว**
  (ไม่รวมกับใคร) หน้าตาอ้างอิงจากแบบฟอร์ม "ใบแจ้งการทำงานล่วงเวลา" ที่ใช้งานจริง
- วันไหนไม่พบข้อมูลสแกนนิ้วของคนนั้น จะแสดงข้อความ "ไม่พบการสแกนนิ้ว" ตรงแถวของวันนั้นเฉยๆ ไม่ข้ามและไม่เอาไปรวมกับวันอื่น
- คอลัมน์ OT รวม (ระบบคำนวณ) เป็นค่าอ้างอิงที่ระบบคำนวณให้อัตโนมัติ ส่วนคอลัมน์อัตรา OT (1 / 1.5 / 3) และลายเซ็นยังเว้นว่างให้หัวหน้างานกรอก/เซ็นด้วยมือเหมือนกระบวนการเดิม

## การตั้งค่าเวลาเข้า-ออกงาน / เกณฑ์ OT

แก้ไขได้ที่ `config.php` ส่วน `attendance`:
- `day_shift_start` / `day_shift_end`: เวลากะเช้า (ค่าเริ่มต้น 08:00-17:30)
- `night_shift_start` / `night_shift_end`: เวลากะดึก (ค่าเริ่มต้น 22:30-08:00 ของวันถัดไป)
- `ot_grace_minutes`: จำนวนนาทีที่ยอมผ่อนผันก่อนติดธง OT (ค่าเริ่มต้น 0 = สแกนออกเกินเวลาเลิกกะแม้แต่นาทีเดียวก็ติดธง)

ระบบจะพิจารณาว่าแต่ละกะเป็นกะเช้าหรือกะดึก **จากเวลาสแกนเข้าจริง** (ใกล้ 08:00 หรือใกล้ 22:30 มากกว่ากัน)
ไม่ได้ยึดจากคอลัมน์ Shift ในไฟล์ Manpower เนื่องจาก ShiftA/ShiftB เป็นการหมุนเวียนรายสัปดาห์ที่ระบบไม่มีตารางล่วงหน้า

## หลักการนำเข้าข้อมูล Manpower

- อัปโหลดไฟล์ Manpower หลัก และ/หรือ Manpower QA ทีละโปรเจค (เลือกโปรเจคที่หน้าอัปโหลด)
- ระบบเทียบ "ลายเซ็นข้อมูล" ของไฟล์ใหม่กับไฟล์ล่าสุดที่เคยอัป ถ้าไม่มีอะไรเปลี่ยน จะไม่แตะฐานข้อมูล
- ถ้ามีการเปลี่ยนแปลง (มีคนเข้าใหม่/ออก/ข้อมูลเปลี่ยน) ระบบจะ**แทนที่รายชื่อเดิมทั้งหมด**ของโปรเจค+ประเภทนั้น
  ด้วยข้อมูลจากไฟล์ใหม่เสมอ (คนที่ออกไปแล้วจะหายไปจากทะเบียนอัตโนมัติ)
- ประวัติการสแกนเวลาเก่าของพนักงานที่ออกไปแล้วจะยังคงอยู่ในระบบ (ไม่ถูกลบ) เพื่อการตรวจสอบย้อนหลัง

## หลักการนำเข้าไฟล์สแกนนิ้ว

- ไฟล์เดียวมีข้อมูลของหลายโปรเจครวมกัน (แยกด้วยคอลัมน์ "แผนก") ต้องเลือกโปรเจคที่จะนำเข้าทุกครั้ง
- แถวที่ซ้ำกับที่เคยนำเข้าไปแล้ว (โปรเจค+รหัสพนักงาน+เวลาสแกนเดียวกัน) จะถูกข้ามอัตโนมัติ ไม่นับซ้ำ
- ระบบจะจัดกลุ่มเวลาสแกนของพนักงานแต่ละคนเป็น "กะการทำงาน" (เข้างาน = สแกนแรกสุด, ออกงาน = สแกนล่าสุด)
  แล้วคำนวณว่าเกินเวลากะหรือไม่โดยอัตโนมัติ

## ความปลอดภัย (สรุป)

- รหัสผ่านผู้ใช้เก็บแบบ hash (bcrypt ผ่าน `password_hash`) ไม่เก็บ plain text
- ทุกคำสั่ง SQL ใช้ prepared statement (PDO) ป้องกัน SQL Injection
- ทุกฟอร์ม POST มี CSRF token
- ล็อกบัญชีชั่วคราว 15 นาทีหลังใส่รหัสผ่านผิดติดต่อกัน 5 ครั้ง
- ไฟล์ `config.php`, `config.example.php`, `README.md` ถูกกันการเข้าถึงผ่านเว็บด้วย `.htaccess` (deny by filename)
  ส่วนโฟลเดอร์ `src/` และ `sql/` มี `.htaccess` ของตัวเอง (deny all) ป้องกันการเข้าถึงทุกไฟล์ข้างในโดยตรง
  แม้จะอยู่ใน public_html ก็ตาม (ถ้า mod_php/.htaccess ใช้งานไม่ได้บนโฮสต์ใด ให้ย้ายไฟล์เหล่านี้ออกนอก public_html แทน)
- ข้อมูลที่แสดงผลบนหน้าเว็บผ่าน `htmlspecialchars` ทุกจุดเพื่อป้องกัน XSS

## ข้อจำกัดที่ควรทราบ (เวอร์ชันเบื้องต้น)

- รองรับ 1 บัญชีผู้ดูแลระบบ (ยังไม่มีระบบสิทธิ์หลายระดับ)
- เปิดใช้งานเต็มรูปแบบเฉพาะโปรเจค TTV FTM-SE ก่อน ส่วน TTV AAT-SE เตรียมโครงสร้างไว้แล้ว
  สามารถเลือกใช้งานได้จากหน้าอัปโหลดทันทีเมื่อพร้อม
- ต้องใช้ PHP 8.0 ขึ้นไป (ใช้ฟังก์ชัน `str_contains`) — ตั้งค่าเวอร์ชัน PHP ได้ใน hPanel > Advanced > PHP Configuration
